Date: 2026-11-19. Source inspection only; **not runtime acceptance**. Baseline: [spec](../specs/review-workflow-usability.md) §3.1–3.3 and [plan](review-workflow-usability.md) P0. User authorization in the task takes precedence over the older draft banners in those documents. This inventory does not approve dependencies or implement commands.

Scope: current desktop clash-review viewer and ribbon-accessible Revit dialogs. Only this new document is owned by P0. Source line references describe the inspected snapshot and can shift during parallel implementation. Existing work in `GameSession.Menu.cs` and `Platform/NativeTextEditor.cs` was not changed or treated as P0 work.

## 1. Reachability rules and key findings

- Do not equate an enum, renderer branch, XML summary or stored binding with a reachable product feature. `InputCatalog.ReviewAction` (`src/BimGo.Core/Scene/InputCatalog.cs:593–611`) filters **Controls/help documentation**, not every runtime input call. Its consumers are `GameSession.Controls.cs:538`, `GameSession.Render.cs:50`, and `KeyMap.cs:934`. Inspect actual callers as well.
- The current three persistent panels are **CLASH REVIEW / INSPECT / ISSUES** (`GameSession.ReviewPanels.cs:31–38`). `RunReviewPanelAction:380–450` is their actual dispatcher. They are action launchers, not Test/Set/result selection lists. Right clicks over them are consumed (`:124–166`); no action context menus exist there.
- Only Scan, Measure and Comment are in the selectable `_guns` array (`GameSession.cs:329–331`); defaults **1 / 2 / 4** retain legacy slot IDs (`:797–804`; Comment action maps to current tool index 2). A separate PlaceGun is still constructed (`:328`) but is not a selectable review tool. Do not revive tools 3/5/6/7/8/9 from their catalog labels.
- **Bookmarks are reachable**, not legacy: toolbar BOOKMARKS → `OpenBookmarks` (`GameSession.Render.cs:563–570,630–646`). Add B and navigation Shift+1…9 still have runtime dispatch (`GameSession.cs:735–741,766–770`).
- Settings → Appearance → **Colour profiles, Water, Grass and Glass keywords** are also reachable (`GameSession.Appearance.cs:149–228`). Omitting these misses real text editors beyond clash/comment fields.
- Test/Set lists currently only select with left click. Rename/Duplicate/Delete live inline inside editor builders. There is no Test/Set context menu, configuration clipboard or F2/Delete object routing (`ClashPanel.cs:393–429,434–583,644–681,687–863`).
- Existing result/group menus are grouping menus, not the full requested command set (`ClashGroups.cs:428–474`). They lack Copy information and Show in Revit; Group has Rename but no F2 routing.
- Shared editor is not the whole text-input surface. Separate char-array editors exist for clash search, rule-value picker search, room search, room-parameter search, Controls search, and markup text. Native Revit WPF inputs are another separate family.

Paths abbreviated below: `Game/` = `src/BimGo.App/Game/`; `Clashes/` = `src/BimGo.App/Game/Clashes/`; `Forms/` = `src/BimGo.Revit/Forms/`. Shortcut names below are **defaults**, not permission to overwrite user bindings.

All custom action menus still need shortcut labels, disabled states, Up/Down/Enter/Esc and Shift+F10/Menu support.

## 4. Proposed exact command and target policy

These are proposed implementation contracts for the next slices, not claims that the current UI implements them.

1. **Focus priority:** native/modal editor → action menu → focused panel/list/readout → viewport. Explicit owner/target survives hover movement. Keys are consumed by owner; Ctrl+A in text never selects clashes; Delete in text never deletes a Test/comment/bookmark; typing R never calls Revit. Typing anywhere in old search panels is replaced with deliberate search focus without losing current Enter/Esc behavior.
2. **Menu targets:** mouse context command freezes a typed target ID plus current document/session token at open. Right-click outside selection selects that row as sole target without activating/navigation; inside selection retains it only for supported multi commands. Keyboard Shift+F10/Menu anchors to focused row/readout. Revalidate target existence and CanExecute at invocation; no index-based target after scroll/filter/rebuild. Empty list has no destructive target; Paste Test/Set can target the explicitly focused list/document.
3. **Text:** menu labels **Undo, Redo, Cut, Copy, Paste, Delete, Select All**; Windows chords Ctrl+Z/Y/X/C/V, Delete, Ctrl+A. Disabled states depend on editability/selection/history/clipboard. Plain text read-only uses **Copy** / **Copy Value**, Ctrl+C; no Cut/Paste mutation. Native dialogs retain native routing. Tab focus navigation must not trigger Minimap/Settings close under an editor/menu owner.
4. **Test:** **Run; Review; Copy Configuration (Ctrl+C); Paste Configuration (Ctrl+V); Rename… (F2); Duplicate; Reset Results…; Delete (Delete)**. Set: **Copy Configuration (Ctrl+C); Paste Configuration (Ctrl+V); Rename… (F2); Duplicate; Add Rule; Add Rule Group; Delete (Delete)**. Copy/Paste one configuration, not RUN ALL checkboxes. A Test payload cannot be pasted into Set list or vice versa. Copy also publishes readable summary to standard Unicode clipboard text.
5. **Clipboard validation:** bounded, explicitly versioned custom Test/Set format, document/session token, known kind, bounded strings/rule depth/count, finite supported tolerance/kind/operators, valid Set references. Reject malformed/stale/foreign-session/foreign-model payloads without arbitrary deserialization or executing clipboard content. Copy takes a deep snapshot; subsequent source edits do not mutate it. Paste creates new ID and distinct name (`Name (copy)`, then numbered copies), respects existing name-length limits, selects inserted row, resets relevant delete arm/scroll/labels. Duplicate button and Paste share the same configuration-copy validation/construction, not result duplication. Test copies only Name/Kind/SetA/SetB/Tolerance/Enabled; never LastRunUtc/LastRunModel/results/groups/issues/history. Set deep-copies nested rules/groups with fresh Set ID; these internal rule groups are configuration, not review clash groups.
6. **Group:** **Copy Group Information (Ctrl+C); Rename… (F2)** plus current grouping/card actions. Copy output is plain text, never a group-creation payload. F2 requires one focused group; no Rename for multi-group selection. Ungroup retains clashes/comments per existing policy; no default Delete-as-Ungroup alias.
7. **Result:** **Copy Clash Information (Ctrl+C); Show in Revit (R); Focus; Status → …** plus existing grouping/assignment/notes/comment actions. Copy summary includes clash/test/group ID/name, status, assignee, notes, element IDs/source/available descriptors, location and measured amount with units. Multiple-copy output follows deterministic displayed/selected order. No result Paste/Duplicate/Delete/F2. Preserve current R and REVIT selection semantics; row-menu Show in Revit and double-click need an explicit singleton target path, not silently reused stale multi-selection.
8. **Issue/reply/bookmark:** issue **Copy Content (Ctrl+C), Open, Go to View, Edit Text…, Delete (Delete)**; reply **Copy Content (Ctrl+C), Delete Reply (Delete)** (no unsupported Edit); bookmark **Copy Bookmark Information (Ctrl+C), Go, Rename… (F2), Set Here, Move Up, Move Down, Delete (Delete)**. Named-object F2 never edits comment/reply content. Preserve exact existing single/bulk/armed confirmations and unlink/save behavior. No issue/group/result/bookmark configuration paste is introduced.
9. **Markup:** typing uses Text commands; canvas uses **Undo Markup, Redo Markup, Clear Markup, Save** and existing tool actions. No selected-shape CRUD is invented. **Settings/read-only auxiliary lists:** **Copy Value/Information**, same existing clearly targeted toggle/reset/navigation/rebind commands; no blanket Delete or Paste. Colour-profile Rename F2 uses its existing named-profile editor; configuration clipboard remains Test/Set-only.
10. **Pointer/menu lifecycle:** context menu opens after stationary right-button release, not mouse-down that may become camera orbit. Right-drag outside UI remains orbit. Esc closes top owner; outside dismiss click is consumed; disabled command cannot run by keyboard. Menu choice closes menu before callback so opening editor/confirm does not get overwritten. Preserve configurable default actions by displaying `Hotkeys` labels, not hard-coded R/Enter/Ctrl+G text. Newly proposed fixed object editing chords need explicit context/conflict tests rather than a global raw-key branch.

## 5. Safe Test/Set thin slice and pitfalls

### Smallest useful menu foundation (after P3 editor contract)

Start with **one Test row menu: Run, Review, Rename…, Duplicate, Delete**, with focused-row F2/Delete and keyboard menu access; then add configuration Copy/Paste with validated payload as a separate slice. Set integration follows using the same command/menu foundation. Do not market the first menu slice as full P6/SC-04 until Copy/Paste is delivered and tested. If P6 is kept atomic, still implement these pieces sequentially and verify before adding Set support.

Relevant seams (all in `Clashes/GameSession.ClashPanel.cs` unless specified):

- `BuildClashTestList:393–429`: clipped row hit-test uses x+36 to avoid Enabled checkbox; add explicit right-target/focus handling without ticking Enabled or immediately running/reviewing. `BuildClashSetList:644–681` analogous; selected Set change resets rule scroll.
- `BuildClashTestEditor:434–583`: extract private target-based handlers for name (`:459–467`), configuration duplicate (`:557–563`), armed delete (`:564–581`); route buttons and menu/keys through them. `BuildClashSetEditor:687–863` equivalents name `:705–713`, `Copy(newId: true)` duplicate `:833–840`, delete-in-use/arm `:841–861`.
- `BuildClashesPanel:284–319`: Run/Review are intentionally deferred until after panel drawing. Shared Review must preserve group pick behavior (`:308–314`), enter clash mode on the requested Test ID, and return early after state transition. Menu must not execute list mutation during iteration. `RequestClashRun:326–342` keeps rerun confirmation; `RequestClashReset:348–364` keeps reset confirmation.
- `ClashSetupChanged:215–222`: preserve document revision/persistence, row/list invalidation, rule structure and colour-profile Set invalidation. `MarkClashTestEdited:600–604` marks prior results stale only on edits, not a copied Test. `ClashSetEdited:987–994` currently depends on `_clashSelectedSet`; do not call it on an unrelated target selected earlier.
- `ForgetCurrentClashIfGone:378–384` and delete `:574–579`: preserve cleanup of deleted current Test/results/review filter. Set deletion must re-evaluate use against actual document Tests, not rely solely on cached `ClashSetRow.UsedBy` at menu-open time.
- `GameSession.Overlays.cs:20–31,79–85,137–148,211–280`: existing dropdown is labels+callback, no per-item enabled/shortcut/keyboard model. Reuse rendering/lifecycle carefully or introduce a small action-menu adapter; do not turn disabled choices into executable callbacks. `BeginOverlays` right-click deliberately closes existing dropdown and **passes through** (`:142–144`): new command-menu policy must consciously handle retargeting vs consumed dismiss, not inherit click-through accidentally.
- `GameSession.Menu.cs:189–202,254–263`: reuse `BeginTextEdit`/commit validation for Rename. Current field adapter work is separate; P0 does not edit it. Caller limits: Test/Set 60, Group 80, notes/comment/reply 280, assignee 60, numeric rule 40, text/custom value 80. Existing general editor renders wrapped text but Enter saves; do not infer multiline newline input merely from wrapping.
- `InputCatalog.cs:63–121,299–310,419–439,593–611`, `GameSession.Controls.cs:521–538`: stored action IDs must not be renamed/reused. New command availability must be context-specific and compatible with configured bindings. In particular Ctrl+Z/Y in editor cannot revive retired file-edit Undo/Redo.

### Specific regression traps

- Test Enabled checkboxes are **RUN ALL membership**, not a clipboard multi-selection. An arbitrary count of checked Tests must not become the implicit menu target.
- Current `DUPLICATE` repeatedly produces the same ` (copy)` suffix. Requested distinct Paste names need a bounded uniqueness allocator, not another concatenation that exceeds max length; keep valid Set references and deep rule copy.
- `_clashDeleteArmed` is an object reference shared by Test and Set editors; menu switch/tab change/target change must not confirm an old target. Menu and keyboard Delete must preserve the same two-step contract, not call `RemoveTest` directly.
- Some `OpenConfirm` callbacks name their Boolean `ok`, but that Boolean represents the optional **skip checkbox**, not acceptance (`Overlays.cs:33–43,96–99`). Acceptance is the callback invocation itself. Do not replicate an `if (ok)` gate from unrelated existing code into new confirmation handlers.
- Comment marker secondary currently removes directly (`Guns/CommentGun.cs:63–69`), unlike armed single-delete and confirmed bulk-delete in COMMENTS. Preserve existing pathways during this scope; do not accidentally inherit direct marker deletion into the new issue-list Delete command or claim all current delete surfaces already confirm.
- Run/Re-run changes statuses and history; Reset/Delete destroys results and may touch linked issue relationships. Never bypass current request/remove/persistence helpers from a shortcut.
- `Hover` is clipping-aware (`Menu.cs:895–899`); use it rather than a raw screen rectangle so offscreen rows do not receive menus. Keyboard targets use IDs, not cached label row objects/indexes.
- Existing result Revit entry (`ClashMode.cs:551–621`) reads selection/current state and warns for large multi-selection. Singleton row-menu/double-click must not call it with stale unrelated selection, but existing R/REVIT bulk behavior must remain intact.
